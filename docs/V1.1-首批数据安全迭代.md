# ReqDoc Studio V1.1 / V8.0.19 迭代记录

## 基线与发布目标

- 基线：V8.0.18（2026-11-05）。
- 目标版本：V8.0.19。
- 本轮保持现有本地资料库、历史记录、整理副本和任务转换模型，不改变用户原始文件。
- 数据安全优先；界面调整只统一视觉与操作层级，不改变既有信息架构。

## 1. 保存失败保护

- 手动保存失败时显示明确错误原因。
- 自动保存失败时在状态栏显示失败原因，并在后续周期重试。
- 保存失败时不清除工作文档的 dirty 状态，不切换文档，不覆盖编辑窗口内容。
- 退出保存失败时明确提示退出会丢失尚未保存的编辑，默认选择留在窗口。
- 解决同步冲突前先保存待处理编辑，避免强制刷新任务列表覆盖编辑器中的未保存文本。

## 2. 来源与任务双侧修改冲突

对每条已有来源关联的任务，使用上一次共同内容作为基线，逐字段比较：

- 来源字段未变：不覆盖任务侧独立修改。
- 只有来源字段变化：同步来源的新值到任务。
- 来源和任务字段都变化且结果不同：记录未解决冲突，不静默覆盖任务。
- 两侧最终变成相同值：自动标记该字段冲突已收敛。

冲突记录包含文档、副本、任务 ID、字段、共同基线、来源新值、任务新值和发现时间。

用户可在“同步冲突”入口选择：
- 采用来源内容：把来源值写入任务。
- 保留任务内容：保留任务值，并把当前来源值设为下一轮比较基线。

删除来源副本、工作文档或任务时同步清理关联冲突。位于回收站或已删除的任务不能直接解决冲突，需先恢复任务。

适用边界：只对已有明确来源关联的导入/工作文档任务执行三方比较；没有来源关联的普通任务不做猜测式匹配。

## 3. 整理规则备份与恢复

- 完整备份新增包含 `reqdoc-data/home/organize-rules.json`。
- 备份说明标明包含数据库、文档、图片和本地整理规则。
- “设置与数据”增加“从备份恢复整理规则”入口。
- 恢复时只读取固定规则成员，不解压任意路径；限制文件大小并校验规则结构。
- 校验成功后才创建当前数据的完整安全备份，再原子替换整理规则。
- 完整恢复副本仍沿用原有独立目录恢复机制，不覆盖当前资料库。

## 4. 文件拖放与批量导入

- 继续使用 Windows Unicode 文件路径接口；对路径执行严格存在性、文件类型和文件属性校验。
- 去重相同路径；一次最多接收 20 个文件。
- 无效路径、缺失文件、目录和不支持的格式单独拒绝，不中断其他有效路径。
- 批量读取逐文件隔离错误：某个文件编码异常或损坏时，其他可读取文件仍可进入导入流程。
- 保留原有归档与事务回滚机制；单文件仍受 20 MB 限制，批量生成任务仍受 500 条限制。

## 5. 界面统一

- 深蓝导航保持不变；主工作区为白色，窗口外层为浅灰。
- 统一树表行高、表头、输入框、下拉框、按钮、标签页和进度条样式。
- 主要确认/保存操作使用强调样式，删除等次要操作保持中性，不改变按钮原有行为。
- 不重排四个主模块，不隐藏原有功能入口。

## 自动化验收覆盖

新增/调整回归：
1. 完整备份包含整理规则，恢复副本可读回规则文件。
2. 手动保存失败保留编辑内容并显示错误。
3. 来源和任务同字段双侧修改会生成冲突，任务值不会被静默覆盖。
4. 冲突可以选择保留任务或采用来源，且更新比较基线。
5. 设置页存在可见的整理规则恢复入口。
6. 一个批次中单个文件读取失败，不影响其他有效文件。
7. 中文路径、重复路径、缺失文件、目录、非法路径和 20 文件上限均有测试。
8. 原生 Windows 文件拖放继续由既有 UI 回归测试覆盖。
9. 主题色、白色工作区、表格与主要按钮样式有独立测试。
