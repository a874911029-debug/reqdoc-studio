# ReqDoc Studio V1.1 首批数据安全迭代

## 基线与范围

- 基线：V8.0.18（2026-11-05）。
- 本批发布目标：V8.0.19。
- 本批只处理数据可靠性与来源同步安全，不提前混入全文检索、批量整理或整体视觉改版。
- 原有本地资料库、文档删除、整理、转任务预览和更新机制保持兼容。

## 1. 保存失败保护

- 手动保存失败时显示明确错误原因。
- 自动保存失败时在状态栏显示失败原因，并在后续周期重试。
- 保存失败时不清除工作文档的 dirty 状态，不切换文档，不覆盖编辑窗口内容。
- 退出保存失败时明确提示退出会丢失尚未保存的编辑，默认选择留在窗口。

验收：模拟数据库写入失败；编辑正文仍留在当前窗口；状态栏和错误提示可见；恢复写入后可再次保存。

## 2. 来源与任务双侧修改冲突

对每条已建立来源关联的任务，使用上一次共同内容作为基线，逐字段比较：

- 来源字段未变：不覆盖任务侧独立修改。
- 只有来源字段变化：同步来源的新值到任务。
- 来源和任务字段都变化且结果不同：记录未解决冲突，不静默覆盖任务。
- 两侧最终变成相同值：自动标记该字段冲突已收敛。

冲突记录包含文档、副本、任务 ID、字段、共同基线、来源新值、任务新值和发现时间。

用户可在“同步冲突”入口选择：
- 采用来源内容：把来源值写入任务。
- 保留任务内容：保留任务值，并把当前来源值设为下一轮比较基线。

删除来源副本、工作文档或任务时同步清理关联冲突，避免遗留不可处理记录。

适用边界：只对已有明确来源关联的导入/工作文档任务执行三方比较；没有来源关联的普通任务不做猜测式匹配。

## 3. 整理规则备份与恢复

- 完整备份新增包含 `reqdoc-data/home/organize-rules.json`。
- 备份说明标明包含数据库、文档、图片和整理规则。
- “设置与数据”增加“从备份恢复整理规则”入口。
- 恢复时只读取固定规则成员，不解压任意路径；限制文件大小并校验规则结构。
- 替换当前规则前，先保存当前编辑并创建一份完整安全备份。
- 完整恢复副本仍沿用原有独立目录恢复机制，不覆盖当前资料库。

## 自动化验收

新增回归覆盖：
1. 完整备份包含整理规则，恢复副本可读回规则文件。
2. 手动保存失败保留编辑内容并显示错误。
3. 来源和任务同字段双侧修改会生成冲突，任务值不会被静默覆盖。
4. 冲突可选择保留任务，并更新来源比较基线。
5. 设置页存在可见的整理规则恢复入口。
